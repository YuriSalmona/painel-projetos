Diagnóstico Territorial

JuremaAbrir plataforma

Objetivo

Dashboard de diagnóstico territorial do Programa Jurema: caracteriza municípios de GO e DF (modo "universo GO+DF") com mapas e gráficos para orientar a atuação do programa, incluindo dados de ICMS Ecológico.

Arquitetura

Aplicativo Streamlit em módulos separados por responsabilidade: interface (dashboard.py), análises (analysis.py), mapas (maps.py), fontes de dados (data_sources.py) e configuração (config.py). Abas 2–4 exibem animação de processamento enquanto calculam. Cache local de ICMS em cache_icms/.

Estrutura

  • dashboard.py — app e abas
  • analysis.py / maps.py — cálculo e cartografia
  • data_sources.py — ingestão de dados
  • cache_icms/ — cache do ICMS Ecológico
  • DEPLOY.md — instruções de publicação
  • logos IC/Jurema (identidade oficial)

Ferramentas

Python + Streamlit; numpy com versão pinada (padrão anti-segfault do Streamlit Cloud, o mesmo do fogo-infiltração). Identidade visual IC (Londrina Solid + Montserrat).

Hospedagem

Streamlit Community Cloud (repositório privado YuriSalmona/Diagnostico-Jurema, branch master). Hiberna após inatividade — comportamento esperado do plano gratuito.

Acessos

Login Google nativo do Streamlit (st.login) restrito ao domínio @cerrados.org, verificado no app. OAuth Client do Google Cloud compartilhado entre os apps do IC; segredos no cofre do Streamlit Cloud.

Inputs

Seleção de município/território (GO+DF); dados públicos municipais e de ICMS Ecológico carregados por data_sources.py.

Outputs

Painéis interativos: mapas temáticos, gráficos e indicadores de diagnóstico por território.

Rotinas

Atualização de dados manual (novo commit). Monitor semanal do painel (segundas 9h) checa disponibilidade. [Periodicidade de atualização das fontes: a confirmar]

Adicionalidade Hídrica

JuremaAbrir plataforma

Objetivo

Quantificar a infiltração hídrica adicional gerada pela proteção de áreas do Cerrado (o "módulo hidrico" citado nas demais plataformas) — base para argumentos de PSA e adicionalidade em projetos de conservação.

Arquitetura

Front-end web hospedado no Vercel (rota /analise) com processamento geoespacial no Google Earth Engine. Em produção, o padrão do módulo é rodar com service account no Cloud Run (EE_USE_ADC=1), conforme documentado no repositório do fogo-infiltração, que reutiliza esta metodologia. [Repositório do front: a confirmar — não localizado na conta GitHub]

Metodologia central

Infiltração = P × Infrac × (1 − C) × Área

P = precipitação média anual CHIRPS 2020–2024; C = Curve Number ANA 2022 (asset projects/ee-yuri/assets/curve_number_ana_2022); Infrac = fração de infiltração por classe MapBiomas (nível 2). Direção validada: floresta 0,30 > pastagem 0,08.

Hospedagem

Vercel (projeto na conta pessoal — URL padrão app-yurisalmonas-projects.vercel.app). Recomendado: renomear o projeto ou apontar subdomínio .cerrados.org.

Acessos

Login restrito a contas @cerrados.org (verificação de domínio). Acesso à plataforma somente pela equipe do IC.

Inputs

Área de interesse (polígono) e parâmetros de análise; dados GEE: CHIRPS, MapBiomas uso do solo, Curve Number ANA.

Outputs

Volume de infiltração adicional (m³/ML) atribuível à proteção da área analisada.

Rotinas

Sob demanda (equipe). Monitor semanal verifica disponibilidade. Atualização das bases GEE conforme novas coleções MapBiomas/CHIRPS.

Repositório e manutenção

[a confirmar] — provável projeto separado ou deploy direto no Vercel. Registrar aqui quando identificado.

Criação de RPPN

JuremaAbrir plataforma

Objetivo

Preparar o requerimento completo de uma RPPN sem precisar operar o SIMRPPN: dados cadastrais, perímetro georreferenciado com validação topológica, mapa técnico no padrão Jurema/IC, documentos e painel de administração das RPPNs.

Arquitetura

App Streamlit com 7 abas + aba Administrar (app.py), apoiado em módulos: geo_utils.py (leitura/validação de geometria, tabela de vértices, aderência), gerar_coordenadas.py (polígono → Excel PONTO,X,Y em UTM SIRGAS 2000), mapa_tecnico.py (satélite, grid, memorial, contexto) e coletor local coletar_rppns.py (dados do SIMRPPN). Guia do usuário servido como HTML estático (enableStaticServing).

Estrutura

  • app.py · geo_utils.py · mapa_tecnico.py
  • gerar_coordenadas.py · coletar_rppns.py
  • static/guia_usuario.html + gerar_guia.py
  • assets/ — logos e malhas IBGE (UFs, municípios)
  • dados/ — RPPNs (fora do repositório em produção)

Ferramentas

Streamlit, Folium/streamlit-folium, GeoPandas 1.1.4, Shapely 2, pyproj 3.7.2, pyogrio, openpyxl, Matplotlib, Pillow; Authlib+httpx para o login (fase 2); numpy 2.5.0 pinado.

Hospedagem

Streamlit Community Cloud, repositório público YuriSalmona/plataforma-rppn. Config sem porta fixa; deploy a cada push.

Acessos

Fase 1 pública, sem login. Fase 2 prevista: login Google restrito a @cerrados.org (modelo já preparado em secrets.toml.example). Dados pessoais de proprietários ficam FORA do repositório enquanto o app é público — cuidado LGPD documentado no README.

Inputs

Dados cadastrais do proprietário e da reserva; perímetro por desenho no mapa, arquivo (shapefile/GeoJSON) ou tabela de vértices, com aderência de vértices e validação topológica.

Outputs

Requerimento pronto para o SIMRPPN, planilha de coordenadas UTM SIRGAS 2000, mapa técnico padrão Jurema/IC e memorial descritivo; saídas gravadas em saidas/.

Rotinas

coletar_rppns.py roda localmente para atualizar a base de RPPNs do SIMRPPN. Monitor semanal checa disponibilidade.

Repositório e manutenção

YuriSalmona/plataforma-rppn (público). Nota de deploy: numpy pinado evita segfault em rebuild do ambiente.

Adicionalidade Hídrica — Fogo & Infiltração

SuindaraAbrir plataforma

Objetivo

Quantificar a infiltração hídrica adicional em áreas de incêndio evitado (manejo integrado do fogo no Cerrado) — conectando o MIF do Programa Suindara ao argumento de adicionalidade hídrica.

Arquitetura

Streamlit + Google Earth Engine. Análises 7a–7e: cicatrizes de fogo (MapBiomas Fogo mensal), gráfico por ano com tendência, mapa de recorrência (tile raster server-side), retângulo de "área poupada" (lados = √área e 0,35 m/s × tempo poupado) e agrupamento de focos FIRMS em incêndios via DBSCAN (2,5 km + gap de 3 dias) com vento ERA5-Land no popup.

Metodologia central

Adicionalidade = Infiltração(proteção) − Infiltração(sem proteção)
Infiltração = P × Infrac × (1 − C) × Área

Área queimada infiltra ~35% menos (Miranda et al. 2010; Resende et al. 2015). Velocidade de propagação 0,35 m/s (Castro & Kauffman 1998 e outros). Validado na Chapada dos Veadeiros 2024: 4.247 ha poupados → 562.331 m³ de adicionalidade.

Inputs

  • Área monitorada (shapefile zipado — universo amostral)
  • Meses de queima prescrita (excluídos da análise)
  • Meses e ano de análise (2000 → último MapBiomas Fogo)
  • Tempo poupado (1–24 h)

Outputs

Hectares queimados vs. histórico, mapas de recorrência e de incêndios individualizados, área poupada (ha) e volume de infiltração adicional (m³/ML). Fase futura: relatório PDF/GeoJSON.

Hospedagem

Streamlit Community Cloud (repo privado YuriSalmona/fogo-infiltracao). Em produção: Cloud Run com service account e EE_USE_ADC=1 (mesmo padrão do módulo hidrico).

Acessos

GEE autenticado por earthengine authenticate (dev) ou service account (produção). Login de usuários no mesmo OAuth Client compartilhado do IC. Assets no projeto ee-yuri.

Rotinas

Análise sob demanda (botão Analisar). Dados-fonte atualizam com as coleções (MapBiomas Fogo, CHIRPS, FIRMS, ERA5-Land). Monitor semanal checa disponibilidade.

Validações pendentes

  • Confirmar qual coleção MapBiomas Fogo foi usada (tenta 4 → 3.1 → 3)
  • Validar codificação do pixel mensal (valor = mês) contra o painel público
  • Rodar com queima real conhecida antes de usar em relatório

Consulta Territorial Povoado

Povos do CerradoAbrir plataforma

Objetivo

Consultar as comunidades tradicionais do Cerrado da base Plataforma Povoado (iniciativa Tô no Mapa) por território — filtros de estado/município, polígono desenhado no mapa ou shapefile/GeoJSON enviado — e gerar relatório baixável com lista de comunidades, texto-resumo e gráficos. Análogo territorial da "Sobreposição de Área com APCAC", aplicado a PCTs.

Arquitetura

Site 100% estático (HTML+CSS+JS puro, sem build e sem backend): dados embutidos extraídos da API da Plataforma Povoado e pré-processados por preprocess.py (shapely). Motor de interseção espacial próprio em JavaScript (bbox + ray casting + interseção de segmentos, ~50 ms para 1.435 municípios). Guia do usuário em modal.

Estrutura

  • index.html · styles.css · app.js
  • dados/ — municipios.geojson, comunidades.json, cerrado.geojson + brutos da API
  • vendor/ — Leaflet 1.9.4, Leaflet.draw 1.0.4 (pt-BR), shpjs 6.1
  • assets/ — logos oficiais Tô no Mapa/realizadores
  • preprocess.py — regenera os dados a partir da API

Dados

6.767 comunidades em 1.435 municípios de 13 UFs (extração 28/07/2026, contagens validadas contra o site oficial). Comunidades vinculadas a municípios, sem coordenada própria: consultas espaciais retornam os municípios interceptados — ressalva documentada no relatório e no guia. Segmentos (28), MATOPIBA e referências bibliográficas por comunidade.

Hospedagem

GitHub Pages, repositório público YuriSalmona/povoado-consulta (branch main, raiz, .nojekyll). Basemap CARTO Positron. Nunca hiberna.

Acessos

Público, sem login — dados já públicos na origem.

Inputs

Estados/municípios (autocomplete), polígono/retângulo desenhado, shapefile .zip ou GeoJSON (reprojeção automática via .prj); refino por segmento, nome e MATOPIBA.

Outputs

Relatório com cards, texto-resumo citável, 4 gráficos e tabela ordenável; downloads: CSV das comunidades (com referências), GeoJSON dos municípios do resultado, PDF via impressão.

Rotinas

Base estática — atualizar rebaixando os JSON da API e rodando preprocess.py (documentado no README). Monitor semanal checa disponibilidade.

Repositório e manutenção

YuriSalmona/povoado-consulta (público). Local: C:\projetos\cerrado-gee\povoado-consulta. Manutenção via Claude Code; deploy automático a cada push (Pages).

Webmap APCAC

Cacimba · MMA + IPH/UFRGSAbrir plataforma

Objetivo

Mapa interativo das Áreas Prioritárias para Conservação de Água do Cerrado (APCAC), produzido para a solicitação IC26017 (apresentação ao MMA), com classificação de prioridade de ação e risco hidrológico em 3 escalas.

Arquitetura

Site estático puro — sem servidor de aplicação, sem build. Dados em PMTiles consultados por HTTP Range requests: abrir o mapa custa ~40 KB, não os 45 MB do repositório. Estratégia raster-na-visão-geral (z3–9) e vetor-no-detalhe (z10, microbacias clicáveis; overzoom sem tiles z11+). limites.pmtiles traz polígonos com contorno desenhado e fill invisível para receber cliques. Os 3 escopos (Cerrado, RHI, UPH) são a mesma geometria com ranqueamento por quantis 5/5/30/60 → classes A/B/C/X.

Estrutura

  • index.html + lib/ (MapLibre GL, pmtiles.js)
  • 4 PMTiles raster/vetor + limites.pmtiles
  • legenda.json (20 classes) · estatisticas.json (154 territórios)
  • Scripts de preparo: recorta_bioma.py (STRtree — de 8h para minutos), gera_estatisticas.py (área geodésica pós-recorte), gera_legenda.py

Ferramentas

MapLibre GL JS, PMTiles, Python (GeoPandas/Shapely com índice espacial STRtree) para o pipeline de dados.

Hospedagem

GitHub Pages (YuriSalmona/apcac-webmap, público). Atenção documentada: o host PRECISA suportar Range requests — um host que devolva o arquivo inteiro quebra o mapa silenciosamente.

Acessos

Público, sem autenticação.

Inputs

Navegação e clique do usuário; malha BHO de microbacias (~201 mil polígonos) pré-processada no pipeline.

Outputs

Classificação por microbacia (prioridade, ação, risco) nas 3 escalas; estatísticas de área por classe para cada território.

Rotinas

Estático: atualização apenas quando o estudo APCAC for revisado (rodar o pipeline Python e commitar novos PMTiles). Monitor semanal checa disponibilidade.

Sobreposição de Área com APCAC ("Está dentro?")

Cacimba · MMA + IPH/UFRGSAbrir plataforma

Objetivo

Responder "minha área está dentro de uma APCAC?": o usuário envia um shapefile zipado ou desenha um polígono e recebe a classe, o risco e a ação recomendada nas 3 escalas, com leitura cartográfica e interpretação técnica (inclusive o texto jurídico sobre áreas de recarga × descarga e APPs da Lei 12.651/2012).

Arquitetura

Página estática com todo o processamento no navegador: shpjs lê o shapefile, turf.js faz interseção e cálculo de área contra os tiles vetoriais z10 do estudo (mesmos PMTiles do webmap, lidos via pbf + DecompressionStream gzip). Sem servidor de processamento — a geometria do usuário não sai do navegador. Registro administrativo de consultas via Supabase (BaaS).

Ferramentas

Leaflet 1.9 + leaflet-draw, shpjs 6, Turf 6.5, pmtiles 3.2, pbf, Supabase JS 2. Identidade IC (Londrina Solid + Montserrat).

Hospedagem

GitHub Pages (YuriSalmona/apcac-analise, público); consome os PMTiles hospedados no repositório do webmap. Há uma v2/ em preparação.

Acessos

Consulta pública sem login. Área administrativa (registro de consultas) autenticada via Supabase. Privacidade: o polígono do usuário é processado localmente no navegador.

Inputs

Shapefile .zip (com .shp, .shx, .dbf e .prj) ou polígono desenhado no mapa.

Outputs

Classe APCAC, risco e ação recomendada por escala (bioma, RHI, UPH), com percentuais de sobreposição e interpretação técnica. Recomendações registradas: aceitar GeoJSON/KML e gerar relatório PDF.

Rotinas

Estático; acompanha as revisões dos PMTiles do webmap. Monitor semanal checa disponibilidade.

Sistema Cerrado (Hub)

ExecutivoAbrir plataforma

Objetivo

Hub de dashboards e plataformas do IC — "Rumo a um milhão de hectares". Visão Geral dos Programas (metas, resultados e OKRs) no topo e colunas de acesso (link tree) por programa: Jurema, Suindara, Povos do Cerrado, Cacimba, Elos do Cerrado e Executivo. É a fonte oficial de agrupamento do painel de projetos.

Arquitetura

App Streamlit de página única: app.py renderiza; todo o conteúdo é editável em dados.py (VISAO_GERAL, HECTARES_POR_PROGRAMA, OKRS, PROGRAMAS). Publicar uma ferramenta nova = trocar None pela URL na lista do programa — o botão sai de "em breve" automaticamente. Sem secrets, roda em modo dev sem login.

Ferramentas

Python + Streamlit. Identidade oficial IC (verde #004F23, bege, laranja como acento; Londrina Solid + Montserrat); cores por programa derivadas do verde/bege, só para wayfinding.

Hospedagem

Streamlit Community Cloud (repo privado YuriSalmona/sistema-cerrado). App público no host — o controle de acesso real é o login do próprio app (se privado no host, colegas são barrados antes da tela de login).

Acessos

Login Google restrito a @cerrados.org. OAuth Client reutilizado dos outros apps do IC — só muda o redirect_uri por app (registrado no Google Cloud Console).

Inputs

Edições em dados.py (metas, OKRs, URLs). [Números atuais são placeholders até conectar o dashboard-fonte]

Outputs

Visão executiva de metas/OKRs e navegação central para todas as plataformas por programa.

Rotinas

Atualização manual em dados.py a cada nova ferramenta ou revisão de OKRs. Monitor semanal checa disponibilidade. Sugestão registrada: migrar para host estático (não hiberna).
